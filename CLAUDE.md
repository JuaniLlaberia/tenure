# CLAUDE.md

Tenure (working name): solo founders hire AI teams that live in Telegram, learn the business once, get better at it with every piece of feedback, and earn autonomy one approved task at a time. Hackathon project; Demo Day is Sun Oct 11, 2026.

## Architecture rules (do not break)

- **The app never calls an LLM. The brain never touches Telegram or the database directly.** The brain uses only the `Tools` and `Store` interfaces from the contract (the LangGraph checkpointer is the one documented exception).
- **The brain streams `Event`s** (async iterators); never return one big result at the end. It never raises out of a stream; it yields an `Error` event.
- **Every team runs the same engine.** Teams differ only by YAML: specialists, task types, fixed `steps` per task type, tools, checks, actions. No per-team graph code.
- **Inside a team, control always returns to the lead.** Specialists never call each other or chat among themselves; they share state.
- **Routing and yes/no decisions go through `decide()`** (Jev via OpenRouter, LLM fallback): which task types a request needs, is it clear enough, does the draft pass the check, is an answer clear. Don't add ad-hoc LLM calls for decisions.
- **Approval and autonomy rules are plain code**, not LLM judgments. Approvals are resolved outside the graph; the graph only pauses for `Ask`.
- **Real actions run only after approval**, unless the task type's autonomy level allows it. Every action is written to the audit log.
- **Finance never moves money** at any autonomy level. No payment tool exists, and none may be added.
- **Teams learn per business.** Feedback (edits, rejects, chat, approved examples) becomes `Lesson`s in the Store and is fed into prompts and checks. Business-specific behaviour lives in lessons, never in templates or code.
- **Ready for parallel tasks.** Tasks run sequentially for now, but all per-task state is keyed by `task_id`; never keep a global "current task".
- Every agent loop has a step limit and a token budget.

## Code conventions

- Python 3.11+, type hints everywhere, async for I/O.
- Pydantic v2 for all models; import shared models from `contract` (`from contract import Approval`), don't redefine them.
- IDs are uuid4 strings generated by whoever creates the record. All datetimes are timezone-aware UTC.
- Small, readable functions; prefer plain code over clever abstractions.
- One blank line between top-level definitions and after imports, never two.
- Docstrings put `"""` on their own lines:
  ```python
  """
  What it does.
  """
  ```
- Keep comments few. Explanations of models, fields and rules belong in `docs/`, not inline.
- Secrets only from environment variables (`.env`, see `.env.example`). Never hardcode or log keys.
- Don't add dependencies without asking.
